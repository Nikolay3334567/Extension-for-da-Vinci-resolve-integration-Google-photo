# Архитектура Cloud Pool

```
 ┌───────────────────────────── Electron (окно плагина) ─────────────────────────────┐
 │  UI (ui/, ES-модули)                                                                │
 │   сетка ◄── <img src=http://127.0.0.1:PORT/SECRET/thumb/KEY?s=384>                  │
 │   плеер ◄── <video src=http://127.0.0.1:PORT/SECRET/stream/KEY>  (Range-запросы)    │
 │        │ IPC (contextBridge, белый список каналов)                                  │
 │  Главный процесс (src/main/)                                                        │
 │   core.js ── oauth.js ──────────────► accounts.google.com / oauth2.googleapis.com   │
 │           ├─ photos.js (Picker API) ─► photospicker.googleapis.com                  │
 │           ├─ drive.js (Drive v3) ────► www.googleapis.com/drive/v3                  │
 │           ├─ media-server.js ─ thumbs.js (дисковый кэш) ─► lh3.googleusercontent… │
 │           ├─ downloader.js (N соединений × Range, докачка) ─► файлы на диск        │
 │           ├─ mp4.js (длительность/fps по Range без скачивания)                      │
 │           └─ jobs.js ─► resolve/workflow-bridge.js ─► WorkflowIntegration.node ─► Resolve Studio
 │                      └► resolve/mailbox-bridge.js ─► JSON-почтовый ящик ◄─ Cloud Pool.lua (Workspace ▸ Scripts)
 └─────────────────────────────────────────────────────────────────────────────────────┘
```

## Почему так

| Требование | Решение |
|---|---|
| «Просто войти в аккаунт» | OAuth 2.0 для установленных приложений: системный браузер + loopback-редирект + PKCE. Google запрещает вход во встроенных web-view, а в браузере пользователь обычно уже авторизован. |
| Вся медиатека Google Фото | С 31.03.2025 Library API читает только созданное самим приложением. Официальная замена — **Picker API**: окно Google Фото (с полным поиском), выбранные элементы сохраняются в локальную медиатеку Cloud Pool. Сессии Picker и 60-минутные `baseUrl` обновляются автоматически, пока сессия жива. |
| Скорость «как в Google Фото» | Превью — серверные миниатюры Google нужного размера (`=wN-hN`, `thumbnailLink=sN`), дисковый LRU-кэш, приоритет самых свежих запросов, отмена запросов для уехавших за экран плиток. Видео — потоковое воспроизведение через локальный Range-прокси (браузер сам запрашивает нужные куски, перемотка мгновенная). Сетка виртуализирована: в DOM только видимые строки. |
| Перенос на таймлайн | Resolve работает только с локальными файлами, поэтому при отправке файл качается с наивысшим приоритетом; задания строго сохраняют порядок, первые клипы ставятся, пока остальные докачиваются. Размещение — через API Resolve (`ImportMedia`, `AppendToTimeline` c `recordFrame`/`trackIndex`). |
| Быстрая загрузка | Файл делится на куски по 8 МБ, 6 keep-alive соединений берут их по порядку (последовательная запись дружит с NTFS/HDD), готовые куски записываются в `.part.json` — докачка после паузы/обрыва/перезапуска. Повторы с экспоненциальной задержкой, обновление токена (401) и `baseUrl` (403), проверка MD5 для Диска. |
| Бесплатная версия Resolve | Workflow Integrations и внешний скриптинг — только в Studio, но меню *Workspace ▸ Scripts* работает везде. Lua-скрипт запускает Cloud Pool и обслуживает JSON-«почтовый ящик» (только фиксированный набор команд, без исполнения присланного кода). |

## Проверенные особенности API Resolve, на которые опирается код

- `AppendToTimeline` clipInfo: `endFrame` — **исключающая** граница (длительность = `endFrame − startFrame`);
  `startFrame/endFrame` — в кадрах исходника, `recordFrame` — абсолютный кадр таймлайна (с учётом стартового таймкода).
- Пересекающийся с существующим клипом `recordFrame` на той же дорожке Resolve **молча отбрасывает** — поэтому
  «На плейхед» ищет свободную дорожку и при необходимости добавляет новую (видео + аудио).
- `CreateTimelineFromClips` капризен к текущему бину — используется `CreateEmptyTimeline` + `AppendToTimeline`.
- С Resolve 20.1 есть promise-API (`InitializePromise`/`GetResolvePromise`); код делает `await` на каждом вызове,
  поэтому работает и с синхронным, и с асинхронным API. `SetAPITimeout(60)` защищает от зависаний при модальных окнах.
- Окно плагина обязано закрывать процесс (`app.quit()`), иначе Resolve держит файлы плагина.

## Безопасность

- Токены — в `account.bin`, зашифрованы `safeStorage` (Keychain/DPAPI/libsecret).
- Заголовок `Authorization` уходит только на домены Google (проверка при каждом редиректе).
- Медиасервер слушает `127.0.0.1`, проверяет секрет в пути и заголовок `Host` (защита от DNS-rebinding).
- UI в изолированном sandbox-процессе с CSP; внешние ссылки открываются только по `https` в системном браузере.

## Тесты

- `test/support/fake-google.js` — фейковые OAuth, Picker API, Drive API и медиа-хосты (Range, редиректы,
  истечение `baseUrl`, ошибки, обрывы, ограничение скорости).
- `test/support/fake-resolve.js` / `fake_resolve.lua` — модели API Resolve с описанным выше поведением.
- `test/unit/*` — модульные тесты всех частей ядра; `test/unit/lua-bridge.test.js` запускает реальный
  `Cloud Pool.lua` под LuaJIT.
- `test/e2e/run.js` — Electron + Playwright: вход, выбор в «Google Фото», превью, метки In/Out, отправка на плейхед
  через Lua-мост, Google Диск, загрузки, настройки, офлайн-медиатека; сохраняет скриншоты в `test-results/`.
